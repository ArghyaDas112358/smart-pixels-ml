## THE KEY DIAGNOSIS — "satisfied, not stuck"
Every seed reports **penalty = 0** on all four constraints. Across all 8 seeds
**cotB lands in 0.483–0.537 — dead on the 0.5 floor** — and 5 of 8 pick the same
late cluster [70–80]. Seed 4042 across 5000 epochs: cotA 0.578→0.611, cotB pinned
at ~0.5. The model hits corr≥0.5, the
penalty goes to zero, and NOTHING then asks for better angles → only the
(position-dominated) NLL remains → router drifts to high-amplitude LATE slices.
It is not a local minimum. **THE FIX (recommended, not yet run): raise
MDMM_MIN_CORR from 0.5 to ~0.85, ramped, with a lambda cap.** 0.85 is known
achievable — seed 2042 hit 0.862 at no NLL cost.

## TWO MEMORY LEAKS (one fixed, one not)
1. **FIXED** — `OptimizedDataGenerator_v3.__getitem__` rebuilt a
   TFRecordDataset+.map(AUTOTUNE)+iterator EVERY batch: ~170 MB/epoch. Cause
   spotted by Ben Weiss. Fix = one persistent iterator per file cached BY PATH
   (on_epoch_end reshuffles the file order, so a batch_index-keyed cache is
   WRONG), `.take(1).repeat()`. Verified bit-identical
   (`smoke_dg_leakfix.py`). Severity was platform-dependent because AUTOTUNE
   sizes buffers to available CPUs.
2. **NOT FIXED** — the per-epoch diagnostic forward pass leaks **122 MB/epoch**,
   isolated by statement-level bisect (`profile_leak.py`, modes sub_lambda /
   sub_fwd / sub_fwd_numpy): it is the EAGER Keras model call `vit(x,
   training=False)` itself. NOT the numpy input (A/B: numpy and tf.Tensor leak
   identically), NOT `.numpy()`, NOT the lambda reads. Likely fix: wrap that
   diagnostic in a `tf.function` built once, or use predict_on_batch.
